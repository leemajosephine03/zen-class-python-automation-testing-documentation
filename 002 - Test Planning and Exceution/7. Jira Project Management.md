# Introduction to Project Management Tools

Project management tools like Jira help plan, track, and manage agile projects effectively. They support Scrum, Kanban, and other methodologies to enhance collaboration and streamline processes.

---

# Key Concepts in Jira & Scrum

## 1. Epic

### Definition
A large body of work that can be broken into smaller tasks (user stories).

### Examples
- Gmail-like application: "Implement Email Management System"
- ATM System: "Develop Cash Withdrawal Module"
- Travel Application: "Build Flight Booking System"

---

## 2. User Stories

### Definition
Short, simple descriptions of a feature told from the user’s perspective.

### Template
> As a [role], I want [feature], so that [benefit].

### Examples

#### Gmail
"As a user, I want to search for emails by keyword so that I can quickly find specific messages."

#### ATM
"As a user, I want to withdraw cash securely so that I can access my money."

#### Travel App
"As a user, I want to view available flights so that I can choose the best option."

---

## 3. Sprint Planning

### Definition
A meeting to decide which tasks (user stories) will be completed during the upcoming sprint (typically 1–4 weeks).

### Steps
- Define sprint goals.
- Pull prioritized stories from the backlog into the sprint.
- Assign tasks to team members.

### Example Sprint Goals

#### Gmail
"Implement email search functionality."

#### ATM
"Develop cash withdrawal and receipt generation."

#### Travel App
"Build flight search and filter functionality."

---

## 4. Backlog

### Definition
A prioritized list of tasks that need to be completed.

### Structure
- Epics: High-level features.
- Stories: Smaller, actionable tasks derived from epics.

### Example Backlog

#### Gmail
- Create Inbox UI
- Implement Email Search
- Add Spam Filter

#### ATM
- Develop PIN Authentication
- Implement Cash Withdrawal

#### Travel App
- Create Flight Search UI
- Develop Payment Gateway Integration

---

## 5. Severity and Priority

### Severity
Indicates the impact of a defect on the system.

#### Levels
- Critical
- High
- Medium
- Low

### Priority
Determines the urgency of fixing the defect.

#### Levels
- High
- Medium
- Low

### Example
- Severity: If the ATM system crashes during a cash withdrawal → Critical
- Priority: Fixing a minor UI issue in Gmail might be Low priority

---

## 6. Release Version

### Definition
A specific version of the product delivered to the customer.

### Examples
- Gmail Version 1.0: Basic email sending and receiving
- ATM Version 1.0: Cash withdrawal and balance inquiry
- Travel App Version 1.0: Flight search and booking

# Step-by-Step Example for a Gmail-like Application

# Epic: Gmail Email Management System

The Epic represents a large feature that needs to be divided into smaller user stories.

### Epic Name
"Gmail Email Management System"

### Description
Build a system to manage emails with features like composing, sending, searching, and managing folders.

---

# User Stories

## 1. Compose and Send Emails

### User Story
As a user, I want to compose and send emails so that I can communicate with others via email.

### Acceptance Criteria
- Users can open a "Compose Email" window.
- Users can type a recipient email address, subject, and body.
- Users can attach files before sending the email.
- Clicking "Send" sends the email successfully.

---

## 2. Email Search Functionality

### User Story
As a user, I want to search for emails by subject or keyword so that I can quickly find important emails.

### Acceptance Criteria
- Search bar should allow entering a keyword.
- Display search results matching the keyword.
- Filter results by date, sender, or folder.

---

## 3. Spam Filtering

### User Story
As a user, I want spam emails to be automatically moved to the spam folder so that I can focus on relevant emails.

### Acceptance Criteria
- Automatically detect spam emails based on predefined rules.
- Move spam emails to the "Spam" folder.

---

## 4. Email Labels and Folders

### User Story
As a user, I want to create labels and folders so that I can organize my emails effectively.

### Acceptance Criteria
- Users can create, rename, or delete labels.
- Emails can be moved to specific folders or labeled.

---

# Sprint Planning

Divide the work into sprints (2 weeks duration).

---

## Sprint 1: Compose and Send Emails

### Goal
Deliver the "Compose and Send Emails" feature.

### Tasks
- Design the UI for the "Compose Email" page.
- Develop APIs for sending emails.
- Implement file attachment functionality.
- Test sending emails and verify functionality.

---

## Sprint 2: Search and Spam Filtering

### Goal
Deliver "Search Functionality" and "Spam Filtering."

### Tasks
- Create a search bar and design the search results page.
- Develop the backend for search functionality.
- Write rules for spam detection and implement spam folder movement.
- Test spam filtering and search accuracy.

---

## Sprint 3: Email Labels and Folders

### Goal
Deliver "Email Labels and Folders."

### Tasks
- Design UI for creating and managing folders/labels.
- Develop APIs to manage folder/label operations.
- Test email organization functionality.

# Bug Reporting Example

## Bug Title
File Attachment Fails When Sending Email

### Steps to Reproduce
1. Open the "Compose Email" window.
2. Add a recipient, subject, and body.
3. Attach a file larger than 10 MB.
4. Click "Send."

### Expected Result
Email with the file attachment is sent successfully.

### Actual Result
Email is sent, but the file attachment is missing.

### Severity
High

### Priority
High
