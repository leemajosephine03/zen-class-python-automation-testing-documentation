# Bug Drafting and Reporting

A Bug Report documents a defect in the software and communicates it to the development team for resolution.

---

# Components of a Bug Report

## 1. Bug ID
Unique identifier (e.g., `BUG_001`).

## 2. Summary
A brief description of the defect.

## 3. Steps to Reproduce
Detailed steps to recreate the issue.

## 4. Expected Result
What should happen.

## 5. Actual Result
What actually happens.

## 6. Severity
Impact on the system (Critical, High, Medium, Low).

## 7. Priority
Fix urgency (High, Medium, Low).

## 8. Environment
Browser, OS, and version details.

## 9. Attachments
Screenshots, logs, or video evidence.

---

# Example Bug Report

| Field | Details |
|---|---|
| Bug ID | BUG_001 |
| Summary | Login button not functional |
| Steps to Reproduce | 1. Open login page.<br>2. Enter valid credentials.<br>3. Click "Login." |
| Expected Result | User should be redirected to the dashboard. |
| Actual Result | Nothing happens on clicking "Login." |
| Severity | High |
| Priority | High |
| Environment | Chrome 115.0.1, Windows 10 |
| Attachments | Screenshot of the issue attached |
