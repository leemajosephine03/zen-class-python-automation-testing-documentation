# Recap of Testing Techniques

Testing techniques are categorized into Static and Dynamic methods to validate software quality effectively.

---

# Static Techniques

## Definition
Involve reviewing and analyzing without executing the code.

## Methods

### Reviews
Document reviews to identify errors or inconsistencies.

### Walkthroughs
Informal discussions to find issues.

### Inspections
Formal peer reviews to detect defects in code or design.

---

# Dynamic Techniques

## Definition
Involve executing the software to validate its functionality and behavior.

---

# Types of Dynamic Testing

## 1. Black Box Testing

### Equivalence Partitioning
Test one value from each input partition.

### Boundary Value Analysis
Test edge values of input ranges.

### Decision Table Testing
Use logical conditions to create test scenarios.

### State Transition Testing
Validate state changes with events.

---

## 2. White Box Testing

### Statement Coverage
Ensure every line of code executes at least once.

### Branch Coverage
Test all possible branches of decision points.

### Path Coverage
Validate all independent execution paths.

---

## 3. Experience-Based Testing

### Error Guessing
Test based on intuition and prior experience.

### Exploratory Testing
Simultaneous learning, test design, and execution.

---

# Extreme Programming (XP)

## Definition
Extreme Programming (XP) is a lightweight, iterative, and incremental software development methodology that emphasizes communication, simplicity, and feedback to deliver high-quality software.

---

# Key Practices

## 1. Pair Programming
- Two developers work together: one writes code while the other reviews.
- Improves code quality and knowledge sharing.

---

## 2. Test-Driven Development (TDD)
- Write test cases before writing code.
- Ensures that the code meets the requirements from the start.

---

## 3. Continuous Integration
- Frequent code integration and testing to identify issues early.

---

## 4. Refactoring
- Improve existing code without changing its functionality.
- Enhances code readability and maintainability.

---

## 5. Customer Collaboration
- Continuous interaction with the customer to refine requirements.

---

## 6. Sustainable Pace
- Avoid overworking the team to maintain productivity and morale.

---

# Advantages of XP

- Quick response to changing requirements.
- High code quality due to frequent testing and refactoring.

---

# Example

Developing an e-commerce website using TDD and pair programming to ensure robust checkout functionality.

---

# Agile Methodology

## Definition
Agile is a flexible and collaborative software development approach that delivers incremental value to customers through iterative cycles.

---

# Core Principles (Agile Manifesto)

1. Customer Collaboration over contract negotiation.
2. Working Software over comprehensive documentation.
3. Responding to Change over following a fixed plan.
4. Individuals and Interactions over processes and tools.

---

# Key Frameworks in Agile

## 1. Scrum

### Features
- Work is divided into short iterations called sprints (2–4 weeks).

### Roles
- Scrum Master
- Product Owner
- Development Team

### Artifacts
- Product Backlog
- Sprint Backlog
- Increment

### Events
- Sprint Planning
- Daily Stand-up
- Sprint Review
- Sprint Retrospective

---

## 2. Kanban

### Features
- Visualize tasks using a Kanban Board.
- Focus on limiting work in progress (WIP) to optimize flow.

---

## 3. Extreme Programming (XP)

Already detailed above.

---

## 4. Lean Development

### Features
- Emphasizes reducing waste and delivering only what adds value.

---

# Advantages of Agile

- Quick delivery of working software.
- High adaptability to changing requirements.
- Enhanced collaboration between teams and stakeholders.

---

# Example

Developing a mobile banking app using Scrum:
- Plan features in sprints.
- Deliver increments.
- Gather user feedback for improvements.
