# Software Testing Life Cycle (STLC)

The Software Testing Life Cycle (STLC) is a series of phases carried out to ensure software quality through effective and systematic testing.

---

# Phases of STLC

## 1. Requirement Analysis

### Objective
Understand and analyze testing requirements from the Software Requirements Specification (SRS).

### Activities
- Identify testable requirements.
- Determine testing types (functional, performance, etc.).

### Outcome
Requirement Traceability Matrix (RTM).

---

## 2. Test Planning

### Objective
Define the testing strategy and plan the test effort.

### Activities
- Create the Test Plan.
- Estimate resources, tools, and timelines.
- Identify test deliverables.

### Outcome
Test Plan Document.

---

## 3. Test Case Design

### Objective
Create detailed test cases and scenarios.

### Activities
- Write test cases based on requirements.
- Review and update test cases.
- Prepare test data.

### Outcome
Test Cases Document.

---

## 4. Test Environment Setup

### Objective
Set up hardware, software, and tools required for testing.

### Activities
- Configure testing servers and tools.
- Prepare test environment checklist.

### Outcome
Ready-to-use test environment.

---

## 5. Test Execution

### Objective
Execute test cases and identify defects.

### Activities
- Run test cases manually or via automation.
- Log defects in the defect tracking system.
- Retest and perform regression testing.

### Outcome
Test Execution Reports and Defect Reports.

---

## 6. Test Closure

### Objective
Conclude the testing process.

### Activities
- Evaluate test completion criteria.
- Document lessons learned and metrics.

### Outcome
Test Summary Report.

---

### Definition
Involves reviewing documentation or code without executing the software.

### Examples
- Code Reviews
- Walkthroughs

---

## 2. Dynamic Techniques

### Definition
Involves executing the software to validate its behavior.

# Use Case-Based Testing

## Definition
Derives test cases from user scenarios to test the end-to-end functionality of the application.

## Example

### Use Case
Login functionality.

### Precondition
User is registered.

### Steps
1. Enter a valid username and password.
2. Click the "Login" button.

### Expected Result
User should be redirected to the dashboard.

# QA, QC, and Testing

## 1. Quality Assurance (QA)

### Definition
A proactive process focused on preventing defects by improving the software development process.

### Focus
Process-oriented.

### Activities
- Process design and audits.
- Setting up best practices and guidelines.

### Example
Ensuring coding standards are followed.

---

## 2. Quality Control (QC)

### Definition
A reactive process focused on identifying defects in the final product.

### Focus
Product-oriented.

### Activities
- Inspecting and testing the product.

### Example
Reviewing test results and ensuring all features work as intended.

---

## 3. Testing

### Definition
A subset of QC, involving the execution of the software to identify defects.

### Focus
Validating functionality and identifying bugs.

### Activities
- Writing and executing test cases.
- Reporting bugs and retesting fixes.

### Example
Testing login functionality with valid and invalid credentials.

---

# Key Differences

| Aspect | QA | QC | Testing |
|---|---|---|---|
| Focus | Process improvement | Product verification | Defect identification |
| Proactive/Reactive | Proactive | Reactive | Reactive |
| Objective | Prevent defects | Detect defects | Detect and fix defects |
